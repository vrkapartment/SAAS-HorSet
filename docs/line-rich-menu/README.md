# LINE Rich Menu ของ HorSet

เมนูล่างในห้องแชท LINE OA — ปุ่มทุกปุ่มในนี้ต่อกับฟีเจอร์ที่ระบบมีอยู่จริงแล้วทั้งหมด
ไม่มีปุ่มที่กดแล้วไม่มีอะไรเกิดขึ้น

**เจ้าหอติดตั้งเองได้จากหน้า ตั้งค่า › LINE OA** — เอกสารนี้อธิบายว่าเบื้องหลังทำงานอย่างไร
และวิธีแก้ดีไซน์/ผังปุ่ม

---

## LINE OA ในระบบมี 3 แบบ

| OA | ใครใช้ | ตารางที่เก็บ token | ผังเมนูที่ใช้ |
|---|---|---|---|
| OA ของหอพักแต่ละหอ | ผู้เช่าของหอนั้น | `workspace_line_settings` | `tenant.json` |
| OA กลาง (fallback) | ผู้เช่าของหอที่ยังไม่ได้ตั้ง OA เอง | ค่า default ใน [lineLiff.ts](../../src/lib/lineLiff.ts) | `tenant.json` |
| OA ทีมงาน HorSet | Super Admin | `super_admin_line_settings` | `super-admin.json` |

> เจ้าของหอ/แอดมินไม่มี OA แยกของตัวเอง — แอดมินเข้ามาใน **OA ของหอ** (ผูกด้วยรหัส 6 หลัก)
> เพื่อรับแจ้งเตือนสลิป แต่ได้เมนูคนละชุดกับผู้เช่าผ่านการผูกเมนูรายบุคคล ดู [เมนูผู้ดูแลหอ](#เมนูผู้ดูแลหอ)

## เมนูผู้เช่า

ภาพ **2500 × 1686 px**, PNG/JPEG, ไม่เกิน **1 MB**

```
┌───────────────────────────┬───────────────────────────┐
│      🧾 บิลเดือนนี้         │      💳 QR พร้อมเพย์        │
├─────────────┬─────────────┼─────────────┬─────────────┤
│  📤 ส่งสลิป   │  📊 ประวัติบิล │ 📱 ติดต่อหอพัก            │
└─────────────┴─────────────┴─────────────┴─────────────┘
```

| ปุ่ม | ชนิด | สิ่งที่ผู้เช่าเห็น |
|---|---|---|
| บิลเดือนนี้ | `uri` `?to=portal` | หน้าบิลรอบปัจจุบัน + มิเตอร์ไฟ/น้ำ + ปุ่มโหลด PDF |
| QR พร้อมเพย์ | `uri` `?to=portal&action=qr` | หน้า `/portal/qr` แสดง QR อย่างเดียวพร้อมยอด |
| **ส่งสลิป** | **`postback` `action=arm_slip`** | บอตตอบให้ส่งรูปสลิปในแชทได้เลย (ดูหัวข้อถัดไป) |
| ประวัติบิล | `uri` `?to=portal&action=history` | หน้า `/portal/history` แสดงบิลย้อนหลังพร้อมมิเตอร์ |
| ติดต่อหอพัก | `tel:` เบอร์ของหอ | โทรออกทันที (ดึงจาก `workspaces.tax_phone`) |

### ปุ่ม "ส่งสลิป" — ส่งสลิปในแชทได้เลย

ปุ่มนี้เป็นปุ่มเดียวที่ไม่เปิดหน้าเว็บ แต่ส่ง **postback** เข้า webhook แทน

ลำดับคือ **"ถามให้จบก่อน แล้วค่อยส่งรูป"**

```
กด "ส่งสลิป"  →  (ถ้าเช่าหลายห้อง) "จะส่งสลิปของห้องไหน?"  [ ห้อง 134 ] [ ห้อง 208 ]
              →  (ถ้าค้างหลายรอบ) "จะส่งสลิปของรอบไหน?"   [ 2026-08 · 3,115฿ ]
              →  "ส่งรูปสลิปได้เลย · ห้อง 134 รอบ 2026-08 ยอด 3,115 บาท"
                 พร้อมลิงก์สำรองไปหน้าอัปโหลดบนเว็บ

ส่งรูปภายในเวลา  →  ดึงไฟล์จาก LINE → เก็บขึ้น Storage → updateBillStatus()
                    (ได้ SlipOK อัตโนมัติ / ปิดบิลเมื่อตรวจผ่าน / แจ้งแอดมิน มาครบ)

ส่งรูปโดยไม่กดปุ่ม  →  ไม่นับเป็นสลิป
```

ถ้าเช่าห้องเดียวและค้างรอบเดียว จะไม่ถามอะไรเลย — กดปุ่มแล้วส่งรูปได้ทันที

**ที่ถามก่อนส่งรูป** เพราะผู้เช่าเห็นว่ากำลังจ่ายบิลใบไหนพร้อมยอดก่อนตัดสินใจ และไม่มีรูปกำพร้า
ค้างใน Storage เวลาเลิกกลางคัน — บิลที่เลือกไว้เก็บใน `tenants.slip_target_bill_id`
เพราะรูปที่ส่งตามมาทีหลังไม่มีข้อมูลติดมาด้วย (ต่างจาก postback ที่พา data มาได้)

**ทำไมต้องบังคับกดปุ่มก่อน** — ถ้านับทุกรูปที่ส่งเข้า OA เป็นสลิป หอที่ใช้ LINE OA คุยเรื่องอื่น
ด้วยจะพังทันที (รูปห้องน้ำรั่วกลายเป็นสลิป) การบังคับกดปุ่มก่อนแก้ที่ต้นเหตุ และทำให้
**ไม่ต้องมีสวิตช์เปิด/ปิดฟีเจอร์นี้ต่อหอเลย**

รายละเอียดทั้งหมดอยู่ใน [line-slip.ts](../../src/features/notification/line-slip.ts) — รวมถึง
การข้าม UID ของแอดมิน และการกันรับซ้ำเมื่อ LINE ส่ง webhook ซ้ำ (ตั้งชื่อไฟล์ตาม `messageId`)

ต้องรัน [database_patch_add_line_slip_upload.sql](../../database_patch_add_line_slip_upload.sql) ก่อนใช้งาน

### ⚠️ ทำไมทุกปุ่มชี้ไป `/tenant-register`

ลิงก์ดูบิลต้องมี `room_id` + signed `token` เฉพาะห้อง แต่ rich menu เป็นปุ่มเดียวที่ผู้ติดตาม
ทุกคนกดร่วมกัน จึงฝังของใครไว้ล่วงหน้าไม่ได้ ต้องมีหน้าที่ยืนยันตัวตนกับ LINE ก่อนแล้วค่อยหาห้อง

และหน้าที่ทำแบบนั้นได้ **ต้องอยู่ใต้ LIFF Endpoint URL ของ channel เท่านั้น** เพราะ LIFF บังคับว่า
`liff.login()` เด้งกลับได้แค่ URL ที่อยู่ใต้ endpoint ที่ตั้งไว้ใน LINE Developers Console
ซึ่งของระบบนี้คือ `https://<domain>/tenant-register`

จึงเอา resolver ไปอยู่ในหน้าเดียวกันกับฟอร์มลงทะเบียน แยกด้วยพารามิเตอร์ `to=portal`:

```
กดปุ่มในเมนู
  → https://liff.line.me/{liffId}?to=portal&workspace_id=…&action=…
  → LINE เปิด Endpoint URL = /tenant-register?to=portal&…
  → liff.login() + getAccessToken()            (อยู่ใต้ endpoint = ผ่าน)
  → POST /api/portal-resolve                   (verify token กับ LINE → หา tenants.line_user_id)
      ├─ เจอ 1 ห้อง   → redirect เข้า /portal?workspace_id=…&room_id=…&token=…&action=…
      ├─ เจอหลายห้อง  → ให้ผู้เช่าเลือกห้องเอง (ไม่เดาแทน)
      └─ ไม่เจอ        → บอกให้ขอลิงก์ลงทะเบียนจากแอดมิน
```

ปลายทาง `/portal` ไม่ติดกฎ endpoint เพราะยืนยันตัวตนด้วย signed token ไม่ได้ใช้ LIFF เลย
ผลที่ได้คือ **ไม่ต้องเปลี่ยน Endpoint URL ใน LINE Developers Console** และลิงก์ลงทะเบียน
ที่ส่งให้ผู้เช่าไปแล้ว (`liff.line.me/{liffId}?p=…`) ไม่พัง เพราะไม่มี `to=portal`

## เมนูผู้ดูแลหอ

ภาพ **2500 × 1686 px** (6 ปุ่ม) — ผังอยู่ใน [`admin.json`](../../src/features/notification/richmenu-templates/admin.json)

```
┌─────────────┬─────────────┬─────────────┐
│ 📊 สรุปวันนี้ │ 🧾 สลิปรอตรวจ │ 🔴 ห้องค้างชำระ │  ← บอตตอบในแชท
├─────────────┼─────────────┼─────────────┤
│ 🏠 หลังบ้าน  │ ⚡ จดมิเตอร์  │ 📑 จัดการบิล  │  ← เปิดเว็บ (login + 2FA)
└─────────────┴─────────────┴─────────────┘
```

| ปุ่ม | ชนิด | สิ่งที่แอดมินเห็น |
|---|---|---|
| สรุปวันนี้ | `postback` `action=admin_summary` | บิลค้างชำระกี่ใบ/ยอดรวม · สลิปรอตรวจกี่ใบ · ห้องว่างกี่ห้อง |
| สลิปรอตรวจ | `postback` `action=admin_pending` | บิลสถานะ `pending` สูงสุด 10 รายการ (ห้อง · รอบ · ยอด · ส่งเมื่อ) |
| ห้องค้างชำระ | `postback` `action=admin_unpaid` | บิลสถานะ `unpaid` สูงสุด 10 รายการ เรียงรอบเก่าสุดก่อน + ยอดรวมทุกใบ |
| หลังบ้าน / จดมิเตอร์ / จัดการบิล | `uri` | `/dashboard`, `/meter`, `/manage-bills` |

ตรรกะการตอบอยู่ใน [`line-admin.ts`](../../src/features/notification/line-admin.ts)

### ทำไมต้องเป็นเมนูอีกใบ

เมนูผู้เช่าถูกตั้งเป็น **default ของทั้ง channel** (`POST /v2/bot/user/all/richmenu`) ทุกคนที่แอด OA
ของหอจึงได้เมนูผู้เช่าหมด รวมถึงเจ้าของหอที่แอดมาเพื่อรับแจ้งเตือนสลิป ซึ่งกดปุ่มไหนก็เจอ
*"ยังไม่พบห้องพักที่ผูกกับบัญชี LINE นี้"* เพราะไม่ใช่ผู้เช่า

LINE มี **per-user link** (`POST /v2/bot/user/{userId}/richmenu/{richMenuId}`) ที่ทับเมนู default
ได้เป็นรายคน เราจึงสร้างเมนูอีกใบแล้วผูกให้เฉพาะ UID ใน `admin_line_user_id`
— คนอื่นยังเห็นเมนูผู้เช่าตามเดิม จัดการทั้งหมดใน [`richmenu-admin.ts`](../../src/features/notification/richmenu-admin.ts)

### ขอบเขตที่ตั้งใจจำกัดไว้

ข้อมูลที่ตอบในแชทเข้าถึงได้ **โดยไม่ผ่าน 2FA** ต่างจากหน้าหลังบ้าน จึงคุมไว้ 3 ชั้น:

1. **อ่านอย่างเดียว** ไม่มีคำสั่งไหนแก้ข้อมูลได้ — การอนุมัติสลิป/แก้บิลต้องทำบนเว็บเท่านั้น
2. **ไม่แสดงชื่อหรือเบอร์ผู้เช่า** แสดงแค่เลขห้อง ลดความเสียหายถ้ามือถือแอดมินหลุดมือ
3. **ตรวจสิทธิ์จาก `admin_line_user_id` ทุกครั้งที่กด** ไม่เชื่อว่าเคยผูกเมนูไว้ เพราะเมนูที่ผูกไปแล้ว
   ยังค้างบนมือถือของคนที่ถูกถอดสิทธิ์ไปแล้วได้

### เมนูถูกผูก/ถอดตอนไหน

| เหตุการณ์ | เกิดอะไร |
|---|---|
| กด **ติดตั้ง/อัปเดตเมนู** ในหน้าตั้งค่า | สร้างเมนูผู้ดูแลใบใหม่ + ผูกให้แอดมินทุกคน |
| แอดมินใหม่ส่ง **รหัส 6 หลัก** ในแชท | ผูกให้ทันทีใน [webhook](../../src/app/api/webhook/line/route.ts) ไม่ต้องรอเจ้าหอมากด |
| กด **ลบการเชื่อมต่อ LINE Admin** | ถอดเมนูของคนนั้นออก แล้วซิงก์รายชื่อที่เหลือ |
| **ปิดสวิตช์เมนูผู้ดูแล** | ถอดออกจากทุกคนและลบเมนูผู้ดูแลทิ้ง |
| กด **ซิงก์เมนูผู้ดูแล** | ผูกให้ตรงรายชื่อปัจจุบันโดยไม่แตะเมนูผู้เช่า |

> ถ้าไม่มีแอดมินคนไหนผูก LINE ไว้เลย ระบบจะไม่สร้างเมนูผู้ดูแลค้างไว้บน LINE
> และภาพเมนูผู้ดูแล **ใช้ภาพต้นแบบของระบบเสมอ** ไม่เปิดให้อัปโหลดเอง เพราะปุ่มเป็นคำสั่งตายตัว

### สองเมนูมีสวิตช์แยกกัน

`richmenu_enabled` คุม **เมนูผู้เช่า** ส่วน `richmenu_admin_enabled` คุม **เมนูผู้ดูแล** — ไม่เกี่ยวกัน

แยกกันเพราะมีเคสใช้จริง: หอที่ไม่อยากให้ผู้เช่ามีเมนูล่าง (อยากให้โทรมาคุยแทน) แต่เจ้าของหอ
ยังอยากกดดูสรุปในแชทเองได้ ถ้าใช้สวิตช์ร่วมกันจะทำแบบนั้นไม่ได้เลย

ผลที่ตามมาที่ต้องรู้:

- **ปิดเมนูผู้เช่า / กดนำเมนูออก → ไม่แตะเมนูผู้ดูแล** แอดมินยังใช้ได้ตามปกติ
- **ปิดเมนูผู้ดูแล → ไม่แตะเมนูผู้เช่า** แอดมินกลับไปเห็นเมนูเดียวกับผู้เช่า
- อยากปิดทั้งหมดต้องกด **2 สวิตช์**

เมนูผู้เช่ามี "เมนูเริ่มต้นของ channel" ให้ยกเลิก ปิดแล้วจึงไม่ต้องลบตัวเมนูและภาพที่อัปโหลดไว้
แต่เมนูผู้ดูแล **ผูกรายบุคคล ไม่มี default ให้ยกเลิก** ปิดจึงต้องถอดออกจากทุกคนแล้วลบตัวเมนูทิ้งจริง
ซึ่งไม่มีอะไรให้เสียเพราะใช้ภาพต้นแบบของระบบเสมอ เปิดกลับเมื่อไหร่ก็สร้างใหม่ได้ทันที

`syncAdminRichMenu` เช็คสวิตช์นี้ **ในตัวมันเอง** ไม่ได้เช็คที่ผู้เรียก — เพราะมีที่เรียก 3 ทาง
(กดติดตั้ง / webhook ตอนแอดมินใหม่ส่งรหัส / ตอนลบ LINE Admin) ถ้าไปกันทีละที่จะพลาดง่าย
แล้วกลายเป็นว่าปิดสวิตช์แล้วเมนูเด้งกลับมาเอง

## วิธีติดตั้ง — เจ้าหอทำเองในเว็บ

**ตั้งค่า › LINE OA › เมนูล่างในแชท LINE** ([RichMenuPanel.tsx](../../src/components/settings/RichMenuPanel.tsx))

กล่องนี้แสดงเมื่อเชื่อมต่อ LINE OA เสร็จแล้ว และให้:

- **สวิตช์เปิด/ปิดเมนูล่าง** สำหรับหอที่ไม่ต้องการใช้
- สถานะเมนู (ใช้งานอยู่ / ยังไม่ได้ติดตั้ง / ปิดใช้งานอยู่) พร้อม **เวลาอัปเดตล่าสุด**
- อัปโหลดภาพเมนูของหอเอง (ใส่โลโก้/สีของหอได้) หรือกลับไปใช้ภาพต้นแบบของระบบ
- ปุ่มติดตั้ง/อัปเดตเมนู และปุ่มนำเมนูออกจาก LINE
- แบนเนอร์เตือนเมื่อข้อมูลในระบบเปลี่ยนไปแล้วแต่เมนูใน LINE ยังเป็นของเก่า

### ปิดสวิตช์ ≠ นำเมนูออก

สองอย่างนี้ต่างกันโดยตั้งใจ อย่าเอามาแทนกัน:

| | ปิดสวิตช์ | นำเมนูออก |
|---|---|---|
| LINE API ที่เรียก | `DELETE /v2/bot/user/all/richmenu` (ยกเลิกเมนูเริ่มต้น) | ยกเลิกเมนูเริ่มต้น **แล้วลบตัวเมนูทิ้ง** |
| ตัวเมนูบน LINE | ยังอยู่ | ถูกลบ |
| ภาพที่อัปโหลดไว้ | ยังอยู่ | ยังอยู่ (เก็บใน Storage ไม่ได้ลบ) |
| กดกลับมาใช้ | เปิดสวิตช์ → กลับมาทันที ไม่ต้องอัปโหลดภาพใหม่ | ต้องกดติดตั้งใหม่ (สร้าง+อัปโหลดภาพใหม่) |
| เหมาะกับ | หอที่ยังไม่อยากใช้ หรือปิดชั่วคราว | เลิกใช้ถาวร / อยากคืนโควตาเมนูของ channel |

ถ้าเปิดสวิตช์แล้วเมนูเดิมถูกลบไปจากฝั่ง LINE (เช่นลบมือใน OA Manager) ระบบจะล้างค่าที่จำไว้
แล้วบอกให้กดติดตั้งใหม่ แทนที่จะปล่อยให้สวิตช์เปิดค้างโดยไม่มีเมนูจริง

ตอนสวิตช์ปิดอยู่ ปุ่มติดตั้งจะถูกล็อกทั้งฝั่ง UI และฝั่ง server action

### ⚠️ ทุกครั้งที่กดอัปเดต = สร้างเมนูใบใหม่

LINE **ไม่มี API แก้ rich menu ที่สร้างแล้ว** มีแค่สร้างใหม่กับลบ ดังนั้น
[installRichMenuAction](../../src/features/notification/richmenu-actions.ts) ทำตามลำดับนี้เสมอ:

```
สร้างเมนูใบใหม่ → อัปโหลดภาพใส่ใบใหม่ → สลับให้ผู้ติดตามทุกคน → ลบใบเก่า
```

ผลตามมาที่ต้องรู้:

1. **ค่าที่ผู้เช่าเห็นเป็นค่า ณ วินาทีที่กดติดตั้ง** ไม่ใช่ค่าสดจาก DB — เจ้าหอเปลี่ยนเบอร์แล้ว
   ไม่กดอัปเดต ปุ่มจะยังโทรเบอร์เก่า ระบบจึงเก็บ `richmenu_contact_uri` / `richmenu_liff_id` /
   `richmenu_template_version` ที่ฝังไปจริงไว้เทียบ แล้วขึ้นแบนเนอร์เตือนเองในหน้าตั้งค่า
   — รวมถึงตอนที่ **ผังปุ่มในโค้ดเปลี่ยน** (เช่นปุ่มส่งสลิปเปลี่ยนจาก uri เป็น postback)
   หอที่ติดตั้งไว้ก่อนหน้าจะถูกเตือนให้กดอัปเดตเองโดยไม่ต้องไล่บอกทีละหอ
2. **ต้องลบใบเก่าทุกครั้ง** ไม่งั้นชน limit 1,000 เมนูต่อ channel — ระบบลบเฉพาะใบที่ตัวเองสร้าง
   (`richmenu_id` ที่จำไว้) ไม่ไปแตะเมนูที่เจ้าหอสร้างเองใน LINE OA Manager
3. ถ้าอัปโหลดภาพหรือสลับเมนูล้มเหลวกลางทาง ระบบจะลบเมนูใบใหม่ทิ้งให้ ไม่ปล่อยขยะค้างใน LINE

ต้องรัน [database_patch_add_line_richmenu.sql](../../database_patch_add_line_richmenu.sql)
ก่อนใช้ฟีเจอร์นี้ (หน้าเว็บจะฟ้องเองถ้ายังไม่รัน)

ภาพที่หออัปโหลดเก็บใน bucket `payment-slips` prefix `line-richmenu/` — bucket เดียวกับ
โลโก้หอพักที่เปิด public อยู่แล้ว จึงไม่ต้องตั้ง bucket หรือ policy ใหม่
ฝั่ง server ดึงไบต์ภาพกลับมาตรวจซ้ำเสมอ ไม่เชื่อผลตรวจจากเบราว์เซอร์

## วิธีติดตั้ง — CLI (สำหรับ OA ทีมงาน และงานฉุกเฉิน)

```bash
# OA ทีมงาน HorSet (ไม่ได้ผูกกับ workspace ไหน จึงไม่มีหน้าเว็บให้กด)
npm run line:richmenu -- --super-admin --image public/line-richmenu/super-admin-menu.png

# ดูผังที่แทนค่าแล้วโดยไม่ยิง LINE
npm run line:richmenu -- --workspace <id> --dry-run
```

ใช้ผังเมนูและกฎตรวจภาพชุดเดียวกับหน้าเว็บ ([richmenu.ts](../../src/features/notification/richmenu.ts))
จึงไม่มีทางที่ CLI กับหน้าเว็บจะติดตั้งเมนูหน้าตาไม่เหมือนกัน

| ตัวเลือก | ใช้ทำอะไร |
|---|---|
| `--prune` | ลบ rich menu อื่นทั้งหมดของ channel นั้นหลังสลับสำเร็จ |
| `--contact tel:0812345678` | ทับปุ่มติดต่อ (ปกติดึงจาก `workspaces.tax_phone`) |
| `--liff-id <id>` | ทับ LIFF ID (ปกติดึงจาก `workspace_line_settings.liff_id`) |
| `--token <token>` | ทับ channel access token ที่อ่านจากฐานข้อมูล |
| `--app-url <url>` | ทับ `NEXT_PUBLIC_APP_URL` |

⚠️ CLI **ไม่บันทึกสถานะลง `workspace_line_settings`** ดังนั้นหน้าตั้งค่าจะยังแสดงว่า
"ยังไม่ได้ติดตั้ง" — ติดตั้งของหอพักจริงควรกดจากหน้าเว็บเพื่อให้ระบบจำสถานะและเวลาอัปเดตได้

## ภาพเมนู

ต้นฉบับเป็น **HTML ไม่ใช่ไฟล์ภาพ** เพื่อให้แก้ข้อความ/สี/ไอคอนได้ด้วย git diff
แล้ว render ออกมาเหมือนกันทุกครั้ง

| ต้นฉบับ | ผลลัพธ์ (ภาพต้นแบบที่ระบบใช้) |
|---|---|
| [images/tenant-menu.html](images/tenant-menu.html) | `public/line-richmenu/tenant-menu.png` |
| [images/super-admin-menu.html](images/super-admin-menu.html) | `public/line-richmenu/super-admin-menu.png` |

```bash
npm run line:menuimg                    # render ทุกไฟล์
npm run line:menuimg -- --only tenant   # เฉพาะเมนูผู้เช่า
npm run line:menuimg -- --only admin    # เฉพาะเมนูผู้ดูแลหอ
```

ภาพ render ไปที่ `public/` เพราะ Server Action ต้องดึงภาพต้นแบบผ่าน URL
(`NEXT_PUBLIC_APP_URL` + `/line-richmenu/...`) ตอนที่หอพักยังไม่ได้อัปโหลดภาพของตัวเอง

สคริปต์ใช้ Chrome/Edge ที่มีในเครื่องถ่าย screenshot ขนาดเท่าภาพจริง (ไม่ต้องลง dependency เพิ่ม)
แล้วตรวจว่าขนาดพิกเซลตรงกับที่ประกาศในผังเมนูและไฟล์ไม่เกิน 1 MB ก่อนจบ
ถ้าไม่มีเบราว์เซอร์ในเครื่องก็เปิดไฟล์ `.html` แล้วบันทึกภาพเองได้

⚠️ **แก้ดีไซน์ต้องแก้ทั้งสองที่ให้ตรงกัน** — ตำแหน่งช่องในไฟล์ HTML (`.cell-*`) ต้องตรงกับ
`areas[].bounds` ในไฟล์ผังเมนู ([tenant.json](../../src/features/notification/richmenu-templates/tenant.json))
เป๊ะ ๆ ไม่งั้นภาพที่ผู้เช่าเห็นจะไม่ตรงกับปุ่มที่กดได้จริง (กด "ส่งสลิป" แล้วไปโผล่หน้า QR)

ฟอนต์ใช้ Prompt จาก `src/app/fonts/Prompt/` ถ้าเบราว์เซอร์โหลดฟอนต์จากไฟล์ในเครื่องไม่ได้
จะถอยไปใช้ฟอนต์ไทยของระบบ — ดูภาพที่ได้ก่อนเอาไปติดตั้ง

## ข้อจำกัดของ LINE ที่ต้องรู้

- ภาพ: **2500×1686** หรือ **2500×843** เท่านั้น, PNG/JPEG, **≤ 1 MB**
- 1 เมนูมีได้ **≤ 20 ปุ่ม**, 1 channel เก็บได้ **≤ 1,000 เมนู**
- `chatBarText` (ข้อความบนแถบเปิดเมนู) **≤ 14 ตัวอักษร**, `label` ของแต่ละปุ่ม **≤ 20 ตัวอักษร**
- ปุ่มแบบ `uri` ต้องเป็น **https** เท่านั้น (ยกเว้น `tel:` กับ `line://`) — ทดสอบบน localhost ไม่ได้
- LIFF app กำหนด **Size** (Compact ~50% / Tall ~80% / Full เต็มจอ) ที่ตัว app ไม่ใช่ที่หน้า
  — หน้าพอร์ทัลบิลยาวและมี QR ให้สแกน แนะนำตั้งเป็น **Full**
- Scope ของ LIFF app ต้องมี **`profile`** ไม่งั้นดึง UID ไม่ได้

## เพิ่มปุ่มใหม่ในอนาคต

ก่อนเพิ่มปุ่ม ให้เช็คว่าปลายทางมีอยู่จริงแล้ว ปุ่มที่ยังทำไม่ได้ตอนนี้เพราะระบบยังไม่มีฟีเจอร์:

- **แจ้งซ่อม** — ยังไม่มี feature ในระบบ (ต้องมี `features/maintenance/` + ตาราง + RLS ก่อน)
- **ประกาศจากหอ** — ยังไม่มีที่เก็บประกาศ
- **สัญญาเช่า/เอกสาร** — ยังไม่มีหน้าให้ผู้เช่าดูสัญญาตัวเอง

ถ้าจะเพิ่มปุ่มที่พาไปการ์ดอื่นในพอร์ทัลผู้เช่า ให้เพิ่มค่าใน `PORTAL_ACTIONS` ที่
[src/lib/portalLiff.ts](../../src/lib/portalLiff.ts) จุดเดียว แล้วรับค่านั้นที่ effect
ของ [portal/page.tsx](../../src/app/(tenant)/portal/page.tsx) — ฝั่งส่ง (tenant-register)
ใช้รายการเดียวกันอยู่แล้ว ไม่ต้องแก้

ถ้าจะเพิ่ม **หน้า LIFF ใหม่ทั้งหน้า** ให้เพิ่มค่า `to=` ใหม่ในหน้า
[tenant-register](../../src/app/(auth)/tenant-register/page.tsx) แทนการสร้าง route ใหม่
เพราะ route ใหม่จะอยู่นอก LIFF Endpoint URL แล้ว `liff.login()` จะไม่ผ่าน
